# pico.rolling-context

Rolling Context preserves Canonical History and projects user messages verbatim. A model round contains an assistant response and its complete tool-result batch; when the next model step starts, the plugin summarizes that round independently without user messages. Summary generation and retry require complete cost estimate settings for the Thread's current provider and model. Without them, rounds stay raw and no summary model call is made. Saving settings does not backfill missed rounds; the latest eligible round can be summarized at the next model step. Rounds remain hot until the Agent invokes `rolling_compact` with the number of recent completed rounds to keep. The action replaces eligible older rounds with their summaries only when its configured cost estimate supports the change. Existing warm summaries remain in the projection.

The cost comparison uses serialized character counts as a proxy for relative token counts. The common characters-per-token factor cancels in the profitability decision; the resulting price-weighted score is not a monetary amount. Images or opaque reasoning replay make the comparison unavailable, so summary generation is paused in those cases as well.

Runtime owns the separate `/compact` and window-limit fallback. It summarizes the final projected context, including user messages and rolling summaries, while preserving user constraints. The host loads this package through the `pico.rolling-context` dynamic entry; its UI runs in the plugin sandbox.
