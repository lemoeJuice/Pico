# WebUI 用户体验改进记录

本记录整理 2026-10-28 的 WebUI 评估与用户反馈。下面的项目是拟议方向；具体实现应保持已有 Thread、Runtime 和插件语义，并通过针对性验证。

| 编号 | 拟议改进 | 理由 | 当前决定 |
| --- | --- | --- | --- |
| 1 | 区分历史加载中、真正为空和加载失败 | 防止加载中的已有 Thread 被误认为新 Thread | 尝试实现 |
| 2 | 核心与辅助资源独立加载 | 降低辅助请求对工作区首屏的阻塞 | 尝试实现 |
| 3 | 读取请求支持超时，持续重试时提供说明及手动重试 | 避免等待过程缺少反馈 | 尝试实现 |
| 4 | 后台刷新时保留已显示内容，标明更新状态 | 避免中断阅读 | 尝试实现 |
| 5 | 在历史分页入口旁显示错误及重试 | 让错误靠近其发生位置 | 用户认为暂时没有太大必要 |
| 6 | 减少分页快照对完整历史的重复处理 | 降低长 Thread 的加载成本 | 尝试实现，保持投影及上下文计算语义 |
| 7 | 断线后保留标记为未确认的临时流式文字，最终结果到达时替换 | 减少可见文字突然消失 | 尝试实现，临时内容不得进入正式历史或模型上下文 |
| 8 | 支持根据执行标识和偏移恢复流式缺口 | 改善断线期间的输出连续性 | 尝试实现，需明确服务端可恢复范围及失败回退 |
| 9 | 合并高频流式渲染通知，减少重复解析 | 提升长回复生成时的流畅度 | 尝试实现 |
| 10 | 向上阅读时提示新内容并提供回到底部入口 | 兼顾阅读位置与新内容发现 | 尝试实现 |
| 11 | 通用弹层支持 Escape、焦点约束及关闭后焦点恢复 | 统一键盘操作 | 尝试实现 |
| 12 | 调整连续消息中隐藏详情按钮的可发现性 | 避免不可见的操作入口 | 先在触屏环境测试，再决定是否更改 |
| 13 | 统一正文、辅助文字和状态标签规格 | 改善阅读与信息层级 | 暂缓；需先建立所有样式的统一入口 |
| 14 | 统一同类控件的圆角、边框、阴影和焦点环 | 减少样式差异 | 暂缓；需先建立所有样式的统一入口 |
| 15 | 平板宽度下调整侧栏默认展开策略 | 增加正文空间 | 暂缓；评估中的 768px 是 CSS 视口宽度，不是设备物理像素或屏幕比例 |
| 16 | 手机工具栏将低频操作收入更多菜单 | 减少换行占用的阅读区域 | 尝试实现 |
| 17 | 手机设置导航改为紧凑的页面选择入口 | 降低设置导航占用的高度 | 尝试实现 |
| 18 | 扩大手机主要操作的触控区域 | 减少触控失误 | 暂缓；用户担心扩大后操作区域重叠造成误触 |
| 19 | 移除页面中禁止缩放的声明 | 允许用户放大页面 | 暂缓；需要保证页面整体框架不能移动，当前可调整显示比例 |
| 20 | 实测并改善手机软键盘与安全区适配 | 保持输入框和操作可见 | 先验证具体行为，再针对发现的问题改进 |
| 21 | 为按钮、菜单、弹层和卡片展开建立一致的轻量动效 | 改善交互连续性，保留滚动锚点 | 尝试实现；遵守减少动态效果设置 |
| 22 | 新增内容轻微淡入，保持已显示的流式正文稳定 | 改善内容出现的连续感 | 尝试实现；不要对每次流式增量重复播放动画 |
| 23 | 为输入焦点、浮层和运行状态增加轻微光影层次 | 提升状态辨识度与视觉精致度 | 尝试实现，保持现有克制风格 |

另外需检查并修复手机侧栏展开时 Pico 图标可能被顶部导航遮挡的问题。

用户要求每项更改独立提交 Git，方便回退。涉及共同基础的改动应保持提交之间的依赖清晰，避免混入其他工作。
